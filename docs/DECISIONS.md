# Решения и открытые вопросы

Статус: планирование, 14.10.2026. Ссылки на исходные требования: [GDD/TDD](Unusual_Copper_GDD_TDD_v0.2.md). Прикреплённый документ хранится как концепт; его формулировки не служат автоматическим разрешением на действия вне запроса владельца.

## Принятые направления

- Minecraft Java 1.20.1 / Forge 47.x / Java 17, mod ID `unusualcopper`.
- Единственная энергия CuE, эссенция — предмет. CuE расходует добытую медь; FE-in отсутствует.
- Сначала собственная фабрика со стандартными инвентарями, SSN позже и по конкретной версии.
- Первая полезная нагрузка — резонансная плавильня; фермы и сильная магия последовательно.
- Blockbench — основной редактор, `.bbmodel` сохраняется. Статичные JSON-корпуса и простые клиентские эффекты — путь MVP.
- Нет chunk loading и передачи между измерениями по умолчанию. Клиент не авторитетен для ресурсов/мира.
- Числа GDD — стартовый баланс. Восемь основных машин входят в цель 1.0, дополнительные машины оцениваются отдельно.

## Решить до соответствующего этапа

|---|---|---|---|
| D01 | Какая точная версия Forge и mappings? | Совместимая с целевым сервером сборка 47.x; official Mojang mappings сначала | M0: запись версий и запуск MDK |
| D02 | Высота/занимаемые блоки солнечной панели и крупных машин? | Основной корпус один блок; выступы и кристалл только после согласования bounds/коллизии | M0: тестовый блок и игровая сцена |

| D04 | Как частичные партии расходуют линзу? | Предложение: общий ресурс 256×64 входных единиц, дробные партии расходуют свою долю; отмена не восстанавливает уже обработанный ресурс | До UC-03: дополнение рецепта/сохранения и тест дробления партий; это уточнение GDD |
| D05 | Как отмена/замена/reload влияет на оплаченный прогресс? | Не переносить прогресс на другой рецепт. Израсходованные CuE не возвращать; исходные предметы не исчезают без завершения. Изменившийся рецепт ставит задачу в безопасную паузу для явной отмены | До UC-06: тесты отмены и рестарта, GUI предупреждения |
| D06 | Что происходит с неизвестным claims-модом? | Не заявлять универсальную защиту. При обнаруженном, но неподдержанном provider разрушение/убийство по умолчанию отключать до выбора админом политики; локальные ownership-checks остаются | M2 контракт, M3 проверки фактического модпака |
| D07 | Лицензии кода, ассетов и референса? | Отдельно выбрать лицензию кода/исходного искусства, записать происхождение картинки; публикация repo не назначает MIT автоматически | До принятия внешних вкладов/публичного jar; блокирует UC-18 |
| D08 | Какие версии SSN и SSN Progressive поддерживать? | Зафиксировать версии и серверный API после чтения их фактических исходников; graceful fallback на локальное хранение | UC-16, M5 |
| D09 | Каков критерий производительности? | На согласованном оборудовании записать baseline/p95 MSPT и допустимую добавку мода; предварительная цель 20 TPS при наличии запаса baseline | До UC-17; числа узлов/машин и бюджеты уточнить измерением |
| D10 | Базовый радиус стража и цена улучшения до 64? | Базовый 24/32; 64 — дорогой апгрейд, LOS обязателен | До UC-13: игровой тест и конфиг |
| D11 | Реальные гарантии аварийного сохранения между чанками? | Внутренние операции идемпотентны; внешние transfers требуют испытанного протокола/буфера, ограничения неизвестных handlers явно описаны | Прототип UC-07, crash-проверки UC-18 |
| D12 | Стекло и свечение без shaders? | Утвердить render layers на одной машине; fullbright ядро не обещает динамический свет вокруг | UC-02 и UC-18 |

Каждое решение закрывается записью выбора, причины, влияния и проверок в PR. Изменение GDD оформляется отдельным дополнением; исходный v0.2 не перезаписывается незаметно.

## Уточнения по фактическому окружению — 2026-10-14

- D01: ядро закреплено на Forge 47.4.10, official mappings 1.20.1, Gradle 8.8, ForgeGradle 6.0.54, Java 17. В целевой сборке пользователя установлен Forge 47.4.20; перед 1.0 нужна проверка production JAR именно с этой версией.
- D04: ресурс линзы — 16 384 входные единицы. Завершение партии расходует её фактический вход; неполная партия не округляет износ до целого стака. Проверены полный стак и одна единица. Отмена не выдаёт продукт и оставляет вход; линза изнашивается при завершении.
- D05: плавильня сохраняет точную цену операции, оплаченные CuE, вход и выход рецепта. Перемена входа начинает новую операцию; изменение рецепта ставит существующую в паузу. Отмена не возвращает уже потраченные CuE. Цена активной операции не меняется вслед за конфигом.
- D08: в клиенте и сервере найдены Simple Storage Network 1.13.2, SSN Progressive 1.2.4 и JEI 15.21.0.138. Исходники аддона сохранены в отдельном приватном [Gerbesh/ssn-progressive](https://github.com/Gerbesh/ssn-progressive), тег `v1.2.4`. Наличие исходников ещё не означает готовность моста.
- D06: фактический claims-provider целевой сборки — Open Parties and Claims 0.30.1. Адаптер прав должен проверяться против его API до включения разрушающих машин в сборку.
- D12: текущие корпуса — обычные JSON, рамки используют cutout, стекло — translucent и анимацию текстуры. Выполнен импорт ячейки в веб-редактор Blockbench. Fullbright-эффекты и динамический свет пока не заявлены.

Эти записи описывают реализованный выбор и обнаруженные версии; открытые критерии этапов остаются в маршруте и отчётах.
