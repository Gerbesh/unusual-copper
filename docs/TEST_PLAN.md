# План проверок и приёмки

**Частично выполнено:** ядро, предметная автоматика, культиватор, коллектор и Пастырь имеют серверные GameTests и игровые сцены; сохранения проверяются также отдельными процессами. Свидетельства и границы приведены в [отчёте по ядру](CORE_VERIFICATION.md), [предметном транспорте](ITEM_TRANSPORT.md), [культиваторе](AREA_CULTIVATION.md), [коллекторе](MAGNETIC_COLLECTOR.md) и [Пастыре](GROWTH_SHEPHERD.md). Полная матрица T01–T36 ещё не пройдена; этот документ задаёт условия дальнейшей приёмки.

Полные сценарии **T01–T36** находятся в разделе 22 [исходного GDD/TDD](Unusual_Copper_GDD_TDD_v0.2.md). Здесь назначены этапы и дополнительные проверки архитектуры/моделей.

## Числовые контрольные примеры

| Сценарий | Ожидаемо при базовых настройках |
|---|---|
| 64 слитка | 128 эссенций, 64 000 CuE после полного расщепления с отводом в ячейку |
| 64 сырой меди | 64 эссенции, 32 000 CuE |
| Полный стек в насытителе, ясный день | 800 активных тиков (40 секунд при 20 TPS), ночью пауза |
| 64 типовых плавки по 200 тиков | 1 280 активных тиков, 15 360 CuE, точный выход рецептов |
| Модовый рецепт 300 тиков, выход ×2 | Одна операция 30 тиков и 240 CuE, выход ×2 |
| Распределение платежа плавильни | Длительности 1/7/20/30/300 тиков дают суммарно 240 без округлительного дюпа |
| Жнец, одна валидная цель | 1 500 CuE, реальная смерть/дроп, без базового XP/player kill |
| Страж, незащищённая валидная цель | 10 HP до защитных модификаторов; 2 500 CuE за выстрел |
| Полная энергия сети после переноса | Сумма исходных/целевых буферов неизменна без генерации и потребления |

Измерять игровые тики отдельно от секунд: при падении TPS реальное время увеличивается. Отдельно подтвердить отсутствие бесконечной медной петли: плавильня улучшает эффективность существующего сырья, не создаёт новое сырьё.

## Виды проверки

- Unit-тесты: CuE/округления, пределы, XP points, чистые правила рецептов и планов; не зеркалить реализацию бессмысленными тестами.
- Forge GameTests: блоки/инвентари/энергия, время операций, соседние сети, паузы, проверка реального результата.
- Интеграционные запуски: клиент, dedicated server, чистый Forge и фактический модпак; поддерживаемые SSN/claims отдельно.
- Ручная игровая приёмка: читаемость GUI/моделей/эффектов, баланс, полный маршрут от добытой меди до автоматики.
- Сохранения: десять обычных рестартов и разрывов сети; отдельно контролируемый аварийный stop до/после commit и сохранения разных чанков. Использовать копию тестового мира.

## Визуальная проверка

День/ночь; дождь; минимальные/обычные частицы; клиент без shaders; инвентарь/рука; все ориентации; 64 маски подключений труб; окна рядом с водой/стеклом; границы высоких моделей и коллизии. Сохранять игровые скриншоты и версии ресурсов. Детальная приёмка: [MODELING](MODELING.md).

## Профиль нагрузки

Создать воспроизводимую сцену 50–100 машин и около 1 000 узлов с активной добычей/ростом/плавкой/переносом. Сначала измерить тот же мир без активности мода; затем выполнить тот же сценарий и интервал прогрева/записи с модом. Сохранить CPU, RAM/JVM, версии, конфиги, TPS, median/p95/max MSPT, время планировщиков и объём пакетов; клиентский FPS измерять отдельно.

До прогона закрыть D09: бюджет добавленной стоимости и критерий p95 MSPT. Цель 20 TPS предполагает достаточный запас baseline. Ни количество машин, ни обещание «не жертвовать TPS» из концепта не заменяет измерение.

## Запись результата

Для каждого сценария: ID, commit, версии/конфиг, шаги, expected/actual, PASS/FAIL/N/A, лог/скриншот, issue при отказе. Матрицу результатов добавлять в `docs/test-results/` по мере появления сборок. Сейчас такой матрицы нет.

Релиз блокируют: воспроизводимый дюп/потеря предметов, server crash, непроверенная смена состояния при restart, обход заявленной защиты, несовместимые чары, ошибки обязательного энергетического цикла или несоблюдённый согласованный бюджет производительности.
