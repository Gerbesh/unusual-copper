# Технический маршрут

Документ описывает целевую архитектуру. Реализованы слои регистрации, серверных настроек, CuE, общих машин, солнечных рецептов и GUI; хранение, предметные трубы, области, специальные машины и интеграции ещё предстоят. Числа и полный набор механик: [GDD/TDD](Unusual_Copper_GDD_TDD_v0.2.md). Разработка ядра: Minecraft 1.20.1, Forge 47.4.10, JDK 17 x64, official mappings 1.20.1. Целевой модпак: Forge 47.4.20.

Официальное руководство подтверждает JDK 17, MDK и Gradle-задачи запуска/сборки: [Forge Getting Started](https://docs.minecraftforge.net/en/1.20.1/gettingstarted/).

## Разделение ответственности

| Слой | Ответственность |
|---|---|
| `registry`, `data`, `config` | Регистрация, рецепты/tags/datagen, серверные пределы и клиентские настройки |
| `energy` | Своя CuE capability, порты, граф, планировщик передачи |
| `machine` | Общие состояния, серверные операции и специальные механики |
| `storage`, `itempipe` | ItemStack/NBT, локальные инвентари, маршруты и остатки |
| `gameplay` | Жезл, грани, области и политика разрешений |
| `network` | Проверенные команды GUI и агрегированные события состояния/эффектов |
| `compat` | Версионные адаптеры SSN, JEI, claims, видов растений/деревьев |
| `client` | Экраны, BER, частицы, звук, превью области |
| `diagnostics` | Счётчики операций, причины остановок, измерения нагрузки |

Базовый package предлагается `io.github.gerbesh.unusualcopper`; окончательное имя фиксируется вместе с MDK. Общую базовую машину делать небольшой: инвентарь, энергия, стороны, redstone, статус, сохранение. Алгоритмы дерева/варки/дропа не прятать в одну огромную иерархию.

## Сервер и сеть

Сервер владеет предметами, энергией, уроном, XP и изменениями мира. Клиент отображает состояние и отправляет намерение игрока. Проверять отправителя, dimension, наличие загруженного чанка, дистанцию, тип блока/menu, права, диапазоны чисел, частоту и актуальность действия. Клиентские координаты не загружают чанки. Выполнять мутации на серверном потоке.

Клиент получает агрегированное состояние и редкие события, а не полную сеть каждый тик. Большие числа энергии синхронизировать пакетами или явным разбиением; не предполагать, что один `DataSlot` передаст любое значение без потерь. [Forge SimpleImpl](https://docs.minecraftforge.net/en/1.20.1/networking/simpleimpl/).

## Энергия CuE

Собственный интерфейс порта: посмотреть запас/ёмкость, симулировать и выполнить приём/выдачу, узнать лимиты направления. Его контракт — часть проекта, а не готовый Forge API. `IEnergyStorage` не публикуем как вход CuE. [Forge Capabilities](https://docs.minecraftforge.net/en/1.20.1/datastorage/capabilities/).

Граф пересобирать при установке/снятии/повороте/изменении стороны и загрузке/выгрузке чанка. Передача учитывает лимит источника, приёмника и каждого использованного ребра; обходная ветка не увеличивает лимит одного порта. Для одинакового приоритета использовать устойчивый round-robin; не допускать голодания потребителя.

M1 сначала проверяет простой граф, цикл, разделение/слияние и узкое место; большие графы требуют ограниченного планировщика. CuE хранится в реальных буферах машин/ячеек, не одновременно в их NBT и «теневом» запасе графа. Промежуточную арифметику выполнять с защитой от переполнения.

## Предметы и операции

`IItemHandler` — обязательная базовая совместимость, SSN — отдельный необязательный адаптер. Симуляция не является блокировкой внешнего инвентаря: перед фактическим изменением повторно проверить условия. Внешний endpoint возвращает фактически извлечённое и непринятый остаток. Незавершённое перемещение хранит предметы в одном внутреннем буфере; не терять и не создавать результат при частичном отказе.

Для долгой операции сохранять ID рецепта, точный вход/NBT, прогресс, оплаченные CuE и промежуточный результат. На завершении снова проверить выход и вход; изменение рецепта или предмета не переносит оплаченный прогресс на другой продукт. Политика возврата/сброса — D05.

Для плавильни транш на шаге `t` можно определить как:

```text
charge(t) = floor(240 × t / totalTicks) - floor(240 × (t - 1) / totalTicks)
```

Сумма за любую длительность строго 240. Нехватка очередного транша ставит процесс на паузу. Сохраняем paid/progress, не списываем всю цену повторно после загрузки. Сначала допускаем только SMELTING с разрешённым сырьём, BLASTING-only — отдельный адаптер.

## Сохранения и восстановление

BlockEntity сохраняет реальные стаки, CuE, настройки/владельца и текущую задачу; transient-кэши/ссылки очищаются на выгрузке. Добавить версию данных и правила миграции до первого стабильного мира. `SavedData` использовать для общих метаданных только при необходимости, не для копии предметов. [Block Entities](https://docs.minecraftforge.net/en/1.20.1/blockentities/), [Saved Data](https://docs.minecraftforge.net/en/1.20.1/datastorage/saveddata/).

Атомарная операция на серверном тике не означает атомарную запись нескольких чанков на диск при аварии. В M2 нужен прототип восстановления перемещений между контейнерами; в M5 — принудительные crash-тесты. Не обещать универсальную crash-safe транзакцию сторонних инвентарей без подтверждённого механизма их API. Ограничения фиксировать до релиза.

## Ограниченные задачи мира

Сканирование распределяется очередями между машинами и тиками. Начальные пределы из GDD: 128 активных операций/тик, 2 048 проверок блоков/тик и 256 кандидатов-сущностей/тик на измерение; до 1 024 узлов сети до профилирования. Это настройки для испытаний, а не доказанная пропускная способность.

Сеть/машины работают только в загруженных чанках. Арборист использует выделенные посадочные точки и разрешения до каждого разрушения; жнец связывает дроп с фактическим действием машины; страж проверяет видимость и права. `FakePlayer` сам по себе не гарантирует соблюдение claims. Адаптеры защищённых территорий должны иметь отдельную матрицу тестов.

## Зависимости и внедрение

1. M0: только Minecraft/Forge, точные версии, Gradle wrapper и CI.
2. M1/M2: собственные контракты CuE/StorageEndpoint, датаген, GameTests и отдельные unit-тесты расчётов.
3. После пробной динамической модели: решение о GeckoLib. Если выбранные основные модели требуют библиотеку, она становится явной runtime-зависимостью; «опциональной» её можно называть только с реализованным альтернативным рендером.
4. M3: проверенные claims/loot/adapters целевого модпака.
5. M5: точные версии SSN/SSN Progressive, JEI и матрица с ними/без них; никаких импортов отсутствующего optional-мода на обязательном пути загрузки.

Выпуск библиотек и mappings проверяется перед фиксацией зависимостей. Проект не переносится на NeoForge/Fabric одновременно с первым Forge MVP.
