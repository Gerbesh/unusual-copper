# Ручное тестирование Unusual Copper (Minecraft 1.20.1)

Запускать команды в PowerShell из `D:\Unusual copper`, установлен JDK 17. Файлы из `D:\Pash_Ver_minecraft` **не меняются**; это отдельные dev-профили Forge.

## Профили

Сбор урожая и картофель в плавильне: `gradlew runClient -PharvestClient`; [режим и правила](CULTIVATOR_HARVEST.md). Маркеры — `CuE HARVEST CLIENT SERVER PASS` и `CuE HARVEST CLIENT PASS`.

Батареи: `gradlew runClient -PbatteryClient`; [правила и ёмкости](BATTERIES.md). Маркер — `CuE BATTERY CLIENT PASS`; проверяются реальные Shift-клик и режимы разрядки, паузы и зарядки.

Проверка понятности привязки труб: `gradlew runClient -PpipeUiClient`; [настройка и ожидаемое поведение](ITEM_PIPES.md). Маркер успеха — `CuE PIPE UI CLIENT PASS`.

| Что проверять | Команда | Миры и настройки |
|---|---|---|
| Только Unusual Copper | `.\gradlew.bat runClient` | `run\` |
| Мост с SSN 1.13.2 | `.\gradlew.bat -PssnClient runClient` | `run-ssn-client\` |
| Мост + Progressive 1.2.4 | `.\gradlew.bat -PssnClient -PssnProgressiveClient runClient` | `run-ssn-client\` |
| Мост + Progressive + JEI 15.21.0.138 | `.\gradlew.bat -PssnClient -PssnProgressiveClient -PjeiClient runClient` | `run-ssn-client\` |
| То же + OpenPAC 0.30.1 | `.\gradlew.bat -PssnClient -PssnProgressiveClient -PjeiClient -PopacClient runClient` | `run-ssn-client\` |
| Только JEI + Unusual Copper | `.\gradlew.bat -PjeiClient runClient` | `run\` |

Перед переключением профиля завершить текущий клиент и его Gradle-процесс. **Не запускайте два клиента на одном dev-каталоге**. Профиль SSN использует только проверенные версии из игнорируемого `.codex-tmp/compat`. JEI получает зависимость из репозитория Maven BlameJared. Для shader/Oculus предусмотрен отдельный профиль `-PshaderClient`; к нему не следует прибавлять `-PsmokeShaders` при ручной проверке, потому что smoke-тест автоматически управляет игрой.

Для ручного мира выберите Creative, плоский мир и отдельное имя, например `uc-manual-m5`. Не открывайте рабочие миры основной сборки. При проверке без SSN сам мост будет отключён и должен корректно показывать причину; обычные хранилища и трубы должны работать.

## Проверки SSN Bridge

1. Взять мост SSN, селектор граней, бочку, предметную трубу и солнечный насытитель. Установить настоящий SSN master и storage cable так, чтобы отмеченный порт моста смотрел **непосредственно** на кабель или master. Селектором повернуть мост на нужную из шести граней.
2. Правым кликом проверить текст подключения. Shift + ПКМ циклически переключает redstone-режим. При неподходящей версии/отсутствии SSN мост не должен выдавать содержимое чужих сундуков.
3. Сеть с двумя SSN links, настроенными на разные физические бочки: поместить в них предметы с одинаковым ID, но разными именами/NBT. Убедиться, что реальный товар не смешивается и не дублируется.
4. Привязать две машины к мостам одного master, включить автоматическую работу. Проверить общую учётную запись запасов; при необходимости дождаться завершения индекса и оставить место в выходах.
5. Полностью заполнить несколько первых хранилищ и оставить свободным дальний порт. Проверить, что предмет в итоге попадает туда; поиск выполняется постранично, не обязательно за один тик.
6. Если установлен OpenPAC, заявить чанк источника/моста за другого игрока, убедиться в отсутствии переноса, затем вернуть права. Проверить возврат работы без утечки содержимого.

## Автоматический клиентский тест JEI

Выполнить `.\gradlew.bat -PjeiClient -PjeiSmoke runClient`. Для совместного клиента: `.\gradlew.bat -PjeiClient -PjeiSmoke -PssnClient -PssnProgressiveClient runClient`. Для полного профиля дополнительно поставить `-PopacClient`. Тест использует только `run-jei-smoke\saves\cue-jei-smoke`, открывает JEI, проверяет четыре серверных рецепта и катализатор, сохраняет `run-jei-smoke\screenshots\cue-jei-solar.png`, закрывает GUI и затем Minecraft. Результат успеха в журнале: `CuE JEI CLIENT PASS`. Smoke-флаг **не** предназначен для обычной игры.

Проверено 15.10.2026: все три прогона (JEI; JEI+SSN+Progressive; JEI+SSN+Progressive+OpenPAC) завершились с кодом 0; на сервере без JEI прошли 117/117 GameTests. Это не полная ручная проверка всех кнопок и модовых рецептов.

## Автоматический клиент без дополнительных модов

Команда `.\gradlew.bat --no-daemon runClient -PsmokeClient -PsmokeClientRu` использует собственный мир `run/saves/cue-smoke` и автоматически закрывает клиент после проверок. В `0.11.0-alpha.1` добавлены сцена трёх классов проводов/ячеек (`cue-energy-tiers.png`) и настоящее меню ячейки III (`cue-cell-iii-menu.png`). Маркеры успеха — `CuE ENERGY TIERS CLIENT MODELS PASS` и `CuE ENERGY TIERS CLIENT MENU PASS`. Заряд 15 999 999 из 16 000 000 проверяется после серверной синхронизации. Этот прогон и 123 обязательных GameTests завершились успешно; свидетельства — [отчёт энергетического этапа](verification/energy-tiers-2026-10-15.txt).

## Автоматическая проверка управления энергией

В `0.12.0-alpha.1` тот же запуск `runClient -PsmokeClient -PsmokeClientRu` дополнительно открывает разветвитель, отправляет настоящие контейнерные C2S-кнопки, получает настройки и усреднённые S2C-показания, затем открывает пассивный монитор возле работающей плавильни. Снимки: `cue-energy-distributor-menu.png`, `cue-energy-monitor-menu.png`, `cue-energy-controls.png`; маркеры — `CuE ENERGY CONTROL CLIENT PASS` и `CuE ENERGY MONITOR CLIENT PASS`. Перед захватом тест ждёт обновлённый кадр. Прогон прошёл; серверная регрессия теперь содержит 129 обязательных GameTests.

## Визуальные сцены 0.13

`gradlew runClient -PvisualClient` открывает принадлежащий репозиторию `cue-smoke` и сохраняет десять кадров `run/screenshots/cue-visual-*.png`: пустое стекло, две фазы потока, обратное направление, угасание, заряд без потока, низкая машина, каталог машин, шесть портов и новые предметы. Маркер — `CuE VISUAL CLIENT PASS`. Для обычного smoke-профиля и визуального профиля отключена пауза при потере фокуса, чтобы автоматический сценарий не зависел от активного окна. Пользовательские инстансы не используются.

Статическая проверка: `python tools/check_visual_assets.py`. Разбор поведения и исходники: [VISUALS](VISUALS.md).

## Проверки JEI

- Навести на медную эссенцию, нажать **R**: открывается категория «Солнечное насыщение», показывающая входной предмет, многоразовую линзу и точное количество получаемой эссенции.
- Навести на слиток меди и нажать **U**: рецепт насыщения должен быть доступен в списке использований.
- В рецепте сырой меди должен быть **1** результат, в рецепте слитка меди **2**. Это читается из текущих серверных датапак-рецептов, а не из UI-констант.
- Открыть JEI-информацию для линзы и эссенции: должны быть разъяснения об износе, солнце и конверсии 500 CuE.
- Повторить обычный клиент **без** `-PjeiClient`: отсутствие JEI не должно мешать запуску игры.

Снимки экрана можно получить F2; лог — `run\logs\latest.log` или `run-ssn-client\logs\latest.log`. При воспроизводимой проблеме приложить версию профиля, шаги, ожидаемое/фактическое поведение и последние строки журнала.

## Ограничения

Нативные headless-тесты SSN, 117 GameTests и три настоящих клиентских smoke-прогона JEI завершены, но это не означает, что все клиентские сценарии, эффекты, рецепты других машин, ручные действия и шейдеры проверены. Стресс-профиль 50–100 машин, crash-атомарность (D11) и полная релизная матрица ещё открыты.
