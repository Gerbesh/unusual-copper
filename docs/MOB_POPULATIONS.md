# Точный учёт популяции для Жнеца — 0.4.1-alpha.1

Это подготовка UC-11: ограниченное построение списка и точный текущий счёт целей для будущей гистерезис-логики «начать > N / оставить M». Механика убийства, сбор дропа и интерфейс Жнеца подключаются следующим этапом.

## Как устроено

`MobPopulations` хранит слабые ссылки на загруженных мобов и секционные деревья с монотонными ID записей. Счёт конкретной области строится через `Ledger.step(budget)`. Один шаг рассматривает не больше указанного числа записей; большая популяция продолжает строиться следующими шагами. Лимит шага не ограничивает размер всей популяции: тест охватывает 300 мобов при шагах по 16.

Область занимает до восьми секций. Подписка создаётся до начального обхода, поэтому новые мобы и изменения уже обработанных записей сразу попадают в её состав. Снимок верхнего ID не позволяет новым появлениям бесконечно отодвигать завершение начального обхода.

**`count()` является полным счётом только при `ready() == true`.** Пока загружается исходный список или ожидается подтверждение появления сущности, машина должна показывать сканирование и ждать. `target()` проверяет актуальный UUID в серверном мире. Смена правил, области или поколения тегов заменяет подписку; старая подписка больше не выдаёт цель. Простаивающие подписки удаляются ограниченным фоновым обходом.

После начального заполнения счёт обновляется событиями изменения состояния. Хуки Minecraft/Forge отслеживают позицию, одиночную и массовую запись SynchedEntityData, добавление/удаление сущности, обычное поле владельца лошади и поводок. Это учитывает перемещение через границу области внутри одной секции, имя, взросление, здоровье и оба стандартных API владения. Полный список сущностей мира каждый тик не обходится.

`ReaperRule` поддерживает конкретные EntityType, теги EntityType и категории. Селекторы объединяются через OR; отдельный явный флаг разрешает пассивных. По умолчанию выбираются взрослые враждебные мобы. Имена, питомцы, владельцы даже без tame-bit, поводки, жители/торговцы и `forge:bosses` исключаются. Безымянный ванильный верблюд без UUID владельца обрабатывается как обычное животное с учётом особенности `Camel.isTamed()`. Привязанные правила неизменяемы; NBT сохраняется отдельно от будущих сетевых команд.

## Хуки и сборка

Forge уже содержит Mixin 0.8.5, отдельной runtime-библиотеки не добавлено. Конфигурация `unusualcopper.mixins.json` обязательна: отсутствие нужной точки внедрения останавливает загрузку вместо работы со скрыто неверным счётом. Используются явные пары official/SRG имён Minecraft **1.20.1**, проверенные по закреплённым mappings. Для dev-запуска конфигурация передаётся аргументом, для обычного JAR — атрибутом `MixinConfigs` в manifest.

Инъекции состоят из наблюдающих callback и не отменяют исходные методы. Одиночные и массовые изменения данных наблюдаются на уровне хранилища, чтобы переопределение `onSyncedDataUpdated` мобом не скрывало обновление. Контракт selector/require описан в [исходнике аннотации Sponge Mixin](https://github.com/SpongePowered/Mixin/blob/master/src/main/java/org/spongepowered/asm/mixin/injection/Inject.java).

## Свидетельства

- Все 53 обязательных GameTests прошли; восемь прежних JUnit также зелёные. Четыре новых теста проверяют 300 мобов, изменения во время построения, тёплый счёт при позиции/имени/одиночных и массовых данных/возрасте/здоровье/владельцах/поводке, отменённый spawn, реальные теги, категории и NBT.
- Существующая дисковая фикстура Пастыря дополнена проверкой, что исходный UUID животного после загрузки entity region учтён ровно один раз и доступен для выбора.
- Обычный reobfuscated JAR запущен отдельным dedicated server **Forge 47.4.20** на копии серверных библиотек целевой установки. Отдельный reobfuscated probe-мод проверил точный счёт 23 мобов, шаги построения и все основные SRG-хуки. Второй процесс загрузил сохранённую корову по исходному UUID и снова учёл её ровно один раз.
- С новыми хуками также прошли прежние проверки OpenPAC 0.30.1 (инвентарь, растение, предмет и Пастырь) и настоящего клиента. Они проверяют сохранение имеющегося поведения; права на убийство Жнецом ещё не проверены.

Логи: [выдержки проверок](verification/mob-populations-2026-10-15.txt). Это проверка чистого Forge с двумя JAR (основной мод и probe), а не полной сборки Better MC.

## Повторение

```powershell
.\gradlew.bat --no-daemon build productionProbeJar runGameTestServer
python tools/run_production_probe.py run-production --java <путь-к-Java-17> --jar build/libs/unusualcopper-0.4.1-alpha.1.jar --probe .codex-tmp/production-probe/unusualcopper-probe-0.4.1-alpha.1.jar
```

Для второй команды заранее установите Forge 47.4.20 в отдельный `run-production` внутри checkout и предоставьте своё существующее принятие EULA. Helper использует loopback, отдельный мир и требует подтверждающий `CuE PRODUCTION POPULATION PASS`; успешного кода Java недостаточно. Повтор той же команды проверяет последующий процесс с сохранённым животным. `productionProbe` — отдельный source set/JAR в игнорируемом каталоге, он не входит в обычный мод.

## Оставшиеся проверки

Перед включением Жнеца нужны реальные смерти, пороги N/M, claims на уничтожение, корректный дроп/отмена событий, отсутствие player-kill/Looting/XP, аварийный буфер, сохранения и UI. Этот этап не закрывает T09–T11 и UC-11.

Не доказаны p95 MSPT и стоимость большого числа перекрывающихся областей: обновление одной записи уведомляет подписки её секций, и этот fan-out требует отдельного профиля. Бюджет `step` ограничивает начальные проверки, а не всю стоимость жизненного цикла сущностей. Также впереди полный модпак, нестандартные модовые lifecycle API и аварийные отключения D11. Точные имена инъекций требуют повторной проверки при смене версии Minecraft.
