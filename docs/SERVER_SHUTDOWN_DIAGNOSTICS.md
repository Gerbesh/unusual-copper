# Диагностика остановок после смены измерения

В версии `0.15.1-alpha.1` добавлены записи `[CuE lifecycle]` для выделенного сервера.
Переход игрока записывает исходное и целевое измерение. Вход в
`MinecraftServer.halt(boolean)` и `stopServer()` записывает стек вызывающего кода,
имя потока и время после последнего перехода любого игрока. Хранится только один
переход без ссылок на игрока или мир; постоянного опроса тиков нет.

Эта диагностика ничего не отменяет и не меняет порядок остановки. Стек с текстом
`Shutdown caller trace (diagnostic, not a crash)` появляется и при штатном
выключении: сам по себе он не означает ошибку.

## Что установлено по двум прежним остановкам

| Архив в `D:\Pash_Ver_minecraft\logs` | Смена измерения | Начало выключения |
|---|---|---|
| `2026-10-16-2.log.gz` | 01:55:29.648, overworld → twilight_forest | 01:55:41.590, через 11.942 с |
| `2026-10-16-1.log.gz` | 02:01:42.846, twilight_forest → overworld | 02:01:52.033, через 9.187 с |

Оба раза миры сохранялись штатно. Свежего crash-report, watchdog или OOM,
объясняющего эти остановки, не найдено. Пользователь не запрашивал остановку.
Ошибки Distant Horizons в этих фрагментах начались **после** начала выключения;
они не устанавливают инициатора. Связь со сменой измерений подтверждается по
времени, причина запроса остановки пока не установлена.

## Какие файлы нужны при повторении

- `logs/latest.log` / соответствующий архив и `logs/debug.log`: искать
  `[CuE lifecycle] Shutdown entry`, включая следующий за ним стек.
- `control/lifecycle-audit.jsonl`: журнал запускателя, отдельно фиксирующий
  отправку `stop`, источник команды и выход Java. Старые остановки произошли
  до добавления этого журнала и не имеют записи инициатора.

`halt` показывает непосредственного вызывающего; команда может быть передана
через диспетчер или очередь, поэтому для установления внешнего источника нужен
также журнал запускателя. Если процесс принудительно завершён снаружи, Java
может не успеть записать стек вообще.

Проверка новой версии: сборка, JUnit, компиляция GameTest-исходников и проверка
упакованных mixin/refmap. Запуск и проверку переходов в игре выполняет пользователь.
