Unusual Copper 0.15.2-alpha.1 — empty battery upgrade / SSN compatibility

Cause established from the local source of both mods:
- BatteryUpgradeRecipe.assemble copies input metadata, then calls
  CopperBatteryItem.stored(result, stored(input)). The old setter always wrote
  CuE:0 even when both recipe preview and input were ordinary untagged batteries.
- D:\SSN Progressive\src\main\java\ru\pashvera\ssn\RecipeData.java
  key() includes the stack's exact serialized NBT.
- ServerManager.verify compares assemble() against the planned exact output;
  error.dynamic_recipe aborts mismatches. The catalogue discards that plan.
  Hence battery I can craft, while empty upgrades II-IV fail validation.

Fix:
- Zero/nonpositive charge removes only CuE and clears the tag only if empty.
- Positive charge remains clamped and stored. Names/other metadata survive.
- Old CuE:0 inputs are normalized on the new crafting result, without mutation
  of the input. No SSN source or installation changes.
